## Detailed findings

### 1. [HIGH] Reflected XSS via GET /tag/<kw>.htm (F-01)

- **CWE:** CWE-79
- **PoC:** https://xyz566.com/tag/X%3Cimg%20src%3Dx%20onerror%3Dalert(document.domain)%3E.htm
- **Detail:** The keyword taken from the URL filename is reflected without HTML-escaping in two places: the document <title> and the "no results" body line. Live evidence (HTTP 200, 2026-10-03, page is Big5-encoded, decoded below): <title>X<img src=x onerror=alert(document.domain)></title> and 很抱歉，沒有搜索到 <font style='color:Black;background-color:Yellow;'>X<img src=x onerror=alert(document.domain)></font> 相關記錄! /tag/ returns HTTP 200 for ANY keyword (even unknown ones), so the reflected page always renders and the XSS does not depend on a search match. Verified with plain curl, browser-header curl, and a real browser: the injected <img> renders as a live image node in the results row and the alert() payload fires, blocking page load. No CSP on the page; PHPSESSID lacks HttpOnly so document.cookie is harvestable. Cloudflare Rocket Loader rewrites script type attributes (data-cf-settings) but execution of the payload is unaffected.

### 2. [HIGH] Reflected XSS via POST /orderstate.htm (F-02)

- **CWE:** CWE-79
- **PoC:** POST https://xyz566.com/orderstate.htm with body: save=true&action=orderstate&oid=Z'%3Cimg%20src%3Dx%20onerror%3Dalert(document.domain)%3E&name=ZTEST&phone=0912345678&email=zt@ex.com&lchcode=0000
- **Detail:** The order-lookup form re-renders all submitted values into single-quoted value='...' attributes without escaping. The re-render happens even when the captcha value is wrong or empty (lchcode=0000), so a valid captcha is not a barrier. Quote-break payload live evidence (HTTP 200, 2026-10-03): <tr><td>訂單編號:</td><td><input name='oid' value='Z'<img src=x onerror=alert(document.domain)>'></td></tr> - the browser parses this as <input name='oid' value='Z'> + a live <img src=x onerror=...> (src resolves to /x, 404 fires onerror) + text '>'. An earlier non-quote payload confirmed raw reflection first: <input name='oid' value='ZOID<script>alert(1)</script>'>.

### 3. [MEDIUM] Reflected XSS on sister domain xyz566.net via </title> break (F-03)

- **CWE:** CWE-79
- **PoC:** https://xyz566.net/tag/x%3Cimg%20src%3Dx%20onerror%3Dalert(1)%3E.htm and https://xyz566.net/tag/x%3C%2Ftitle%3E%3Cscript%3Edocument.title%3D%22XSS_EXECUTED%22%3B%3C%2Fscript%3E.htm
- **Detail:** .net serves the same /tag/ handler with a different template. Every /tag/ URL returns a custom 404 page (~21.7 KB) but the keyword is still reflected unescaped in <title>: <title>x<img src=x onerror=alert(1)></title>. Because the reflection sits inside <title>, a </title> break injects a raw <script> element directly into <head>: <title>x</title><script type="5c4507ee...-text/javascript">document.title="XSS_EXECUTED";</script></title> (Rocket Loader rewrites the type attribute but still executes the script at DOM-ready). The 404 status does not stop execution - the page fully renders. Related: a raw < in a non-/tag/ path on .net returns an HTTP 400 ASP.NET runtime-error page (執行階段錯誤) disclosing X-AspNet-Version: 4.0.30319 and X-Powered-By: ASP.NET.

### 4. [MEDIUM] Wildcard subdomains 301 to http://xyz566.net/ (F-04)

- **CWE:** CWE-916
- **PoC:** http://m.xyz566.com/ (same for shop./mail./admin./dev./test./ftp./webmail./cpanel./api.xyz566.com)
- **Detail:** 10 plausible subdomains resolve and 301-redirect to a DIFFERENT domain over plain HTTP: <h1>Moved Permanently</h1><p>The document has moved <a href="http://xyz566.net/">here</a>.</p> (www.xyz566.com correctly 301s to https://xyz566.com/). Users typing m./shop./admin. are silently sent to the .net sister domain over plain HTTP - a confusing two-domain footprint for an e-commerce site, and the redirect target is the domain that carries the F-03 XSS. The wildcard behavior suggests a stale or intentional park vhost.

### 5. [LOW] Latent DOM XSS sink in search suggestions (F-06)

- **CWE:** CWE-79
- **PoC:** GET /lch_ajax.php?action=get_searcher_list&kw=<term> - returned terms are injected unescaped by the frontend: html += "... title='"+f[0]+"'><a ...><td ...>"+f[0]+"</td><td ...><nobr>"+f[1]+"</nobr>...</div>"; esl.innerHTML = html;
- **Detail:** /lch_ajax.php returns previously searched terms (tab-separated: term / 搜 N 次 / id); the suggestion dropdown injects f[0] and f[1] unescaped into a title='...' attribute and body content via innerHTML. A logged term containing ', " or < would break out of the attribute or inject HTML when the dropdown renders. Logged terms so far contain / = $ but no quotes or angle brackets (e.g. $300 輪, $25 wheel of fortune, ${10000176 10000292}), and terms are only logged when a /tag/ search yields results - not currently exploitable; re-test after the F-01 fix.

### 6. [INFO] Origin IP leak + broken navigation redirect (F-05)

- **CWE:** CWE-200
- **PoC:** GET https://xyz566.com/order3/send1.htm -> 302 Location: http://149.28.84.181/order2/send1.htm
- **Detail:** The 手動下單 (manual order) nav link points to /order3/send1.htm, which 302-redirects directly to the origin server's IP over plain HTTP - an origin leak enabling CDN bypass, plus a broken user flow: the /order2/ path on the origin is currently unreachable (direct http://149.28.84.181/ on :80 gets no response).

### 7. [INFO] EOL stack disclosure, cookie flags, no CSP, ASP.NET error pages (F-07)

- **CWE:** CWE-200
- **Detail:** Every page on both domains discloses X-Powered-By: PHP/5.6.31 (EOL since 2018) and X-Powered-By: ASP.NET; .net malformed paths additionally return a full ASP.NET runtime-error page with X-AspNet-Version: 4.0.30319. PHPSESSID is set with path=/ only - no Secure, no HttpOnly, no SameSite (HTTPS-only plus HSTS preload mitigates the missing Secure flag; the missing HttpOnly is what makes F-01/F-03 cookie harvesting feasible). No Content-Security-Policy on either domain, so all three XSS findings execute unimpeded. Positives: HSTS max-age=31536000; includeSubDomains; preload and X-Content-Type-Options: nosniff. robots.txt hides all PHP endpoints (Disallow: /*.php), confirming /search.php, /lch_ajax.php and /lchcode.php (4-digit PNG captcha, no rate limiting) are real endpoints.

## Negative results

- SQLi: cart_add probes on /lch_ajax.php (number=' OR 1=1, UNION variants) returned identical empty-cart responses - no error-based leakage.
- /search.php?keyword=... and /search.htm do not reflect the keyword; the /question.htm feedback form (valid captcha) reflects no user input.
- /.env, /admin.php, /wp-login.php all return the site's custom 404 page; no directory listings.
- Session cart via /lch_ajax.php (cart_get|cart_add|cart_remove|cart_clear; product codes such as DCU0041) - no reflected input in cart pages.
- sitemap.xml lists 1949 catalog pages; no sensitive paths beyond the above.
